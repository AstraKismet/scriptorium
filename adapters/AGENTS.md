Any translation, localization, or i18n task in this repository goes through the
Scriptorium pipeline in `tools/scriptorium/`. Do not translate documents by reading
them and writing a translated copy — structure and terminology regress silently that
way, and nothing catches it.

Read `tools/scriptorium/skill/SKILL.md` before starting, and
`tools/scriptorium/skill/reference/zh-TW.md` before any Traditional Chinese work.

The loop:

```bash
LX="lx"                             # or `python -m scriptorium`
$LX extract <src> --lang <lang>     # parse + mask + reuse translation memory
$LX todo    <src> --lang <lang>     # pending segments as JSON
$LX apply   <src> --lang <lang> --file draft.json
$LX check   <src> --lang <lang>     # must exit 0
$LX render  <src> --lang <lang> -o i18n/<lang>/<path>
$LX commit  <src> --lang <lang>     # only after human review
```

Or, when a backend is configured in `lx.config.json`, the whole loop in one command:

```bash
$LX run <src> --lang <lang> --polish
```

`$LX providers` lists configured backends. `$LX web` opens the review workbench for
a human.

`$LX terms <src> --lang <lang>` proposes glossary rows from the source text with
the target column left empty. Propose, do not fill: how a name renders is the
human's decision, and an unfilled row enforces nothing until they make it.

`⟦n⟧` in a segment is protected content — copy it verbatim, reposition it freely,
never invent or drop one.

When `check` fails, re-translate only the flagged segments (`todo --all` includes a
`fix` note on each). Never re-run a whole document to fix a few segments.

Never report a translation as complete unless `check` exited 0. The report at
`.lx/reports/<doc>.<lang>.json` is generated by the checker; do not write one by hand.
